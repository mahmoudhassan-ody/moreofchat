# More Of Chat — P1 Implementation Plan

> **For Claude:** implement task-by-task. Write the failing test, run it, confirm it fails for the right reason, then implement. Commit after every task. Stop at each boundary for review.

**Goal:** A grounded answer, retrieved from a real corpus, measured by a real number. At the end of P1 the eval suite produces a report you can act on — which is the first point in this project where "is it good?" has an answer other than an opinion.

**Prerequisite state:** weeks 1–2 complete, 498 tests green, both fixtures frozen and reproducing byte-identically, both case files grounded, CI validated.

**Read first:** `CLAUDE.md`, design doc §2 (direct APIs), §7 (retrieval), §19 (config surface), harness spec §5.1–5.3 and §8.1.

**Standing constraints, all test-enforced:**
- No provider SDK outside its adapter; no endpoint or `base_url` outside `src/moc/llm/`
- No Arabic literals or magic numbers in `src/moc/arabic/`; everything lexical is config
- Every tenant-scoped table: RLS with the `nullif` predicate, `FORCE ROW LEVEL SECURITY`, `moc_app` grant
- One statement per `op.execute()`
- Tests use `app_engine`, never the table owner
- **Sabotage-and-revert with a scratchpad copy, not `git checkout`** — the baseline may be uncommitted

## Task 20: The case runner

The thing that has been missing since week 1. It drives the orchestrator over the case files and produces the report.

**Files:** `src/moc/evals/runner.py`, `tests/evals/test_runner.py`

**Design decision, settled:** the runner performs **real fusion over the ingested fixture corpus**. It does *not* feed `gold_chunks` to the orchestrator.

Feeding gold chunks measures generation while skipping retrieval — and retrieval is the half most likely to fail on Arabic. `edu-0015` exists precisely to test the retrieval path; a runner that hands it the right chunk asserts nothing. `gold_chunks` remain the ground truth for `retrieval_recall_at_5`, which is a *measurement* of what fusion returned, not an input to it.

**Tests first:**

```python
async def test_runs_a_single_turn_case_end_to_end()
async def test_multi_turn_case_carries_state_between_turns():
    """edu-0007: three turns, slots accumulating."""

async def test_retrieval_is_real_not_injected():
    """Assert the retriever was called and gold_chunks were NOT passed in.
    The whole design decision, pinned."""

async def test_recall_is_measured_against_gold_chunks_not_fed_from_them()
async def test_a_case_with_empty_gold_chunks_is_excluded_from_recall():
    """Not counted as a failure. Many adversarial cases have none."""

async def test_deterministic_checks_run_before_the_judge():
    """Cheap, non-flaky, and they cover both hard gates. A case failing
    stage 1 should not cost a judge call."""

async def test_run_metadata_records_config_hash_and_prompt_version()
async def test_a_provider_error_marks_the_case_errored_not_failed():
    """An outage is not a quality signal, and folding it into the failure
    rate corrupts the baseline."""

async def test_uses_batch_endpoints_for_a_full_run()
```

**Acceptance:** `pytest -m eval` runs all 39 cases through both stages and writes a report. `eval-full` and `eval-judge` stop failing on the missing-runner error. **This is the first real number in the project — read it, do not tune to it yet.**

## Task 21: The `channel_accounts` bootstrap

A security decision, not a task. Carried since week 2.

**The problem:** every tenant-scoped table gets RLS, but this lookup runs *before* a tenant context exists — its job is to establish which tenant a message belongs to. Under RLS with no tenant set it returns nothing; setting a tenant first requires the answer.

**Recommended shape:** a `moc_lookup` role with `SELECT` on a view exposing only the resolving columns — `id`, `tenant_id`, `channel`, `address`, `secret_ref`. No access to anything else, no access to the base table.

**Tests first:**

```python
async def test_lookup_role_can_resolve_a_channel_account()
async def test_lookup_role_cannot_read_conversations()
async def test_lookup_role_cannot_read_the_base_table()
async def test_lookup_role_cannot_read_secrets_beyond_the_reference()
async def test_the_view_exposes_only_the_resolving_columns():
    """Column-list assertion. A later ALTER adding a column to the view is
    a privilege escalation that no other test would catch."""

async def test_an_unknown_address_is_refused_before_tenant_resolution()
```

**Acceptance:** the webhook path resolves a tenant using `moc_lookup` and nothing else, and the isolation tests prove the role's reach is bounded.

## P1 exit criteria

Closed 2026-08-19. Each line carries the evidence rather than a tick, and the
lines that cannot be satisfied by completing this plan have been moved to P1b
rather than left to look outstanding — a checklist that finishing the plan
cannot clear is a second, unwritten plan.

- [x] **Sinai ingests through the real pipeline; outbox drains; reconciliation clean.**
  `test_the_sinai_fixture_ingests_through_the_real_path`,
  `test_the_outbox_drains_to_empty_on_success`, and four reconciliation tests
  in `tests/retrieval/test_vectors.py`.
- [x] **The broker fixture does not ingest — met by decision, not by default.**
  The criterion originally said "both fixtures". Ingesting the broker units
  into `kb_chunks` creates a second path to a unit's price that bypasses the
  availability filter and the `as_of` disclosure: `sold_unit_offered_rate`
  would read zero while a sold unit's price sat in a retrieved chunk. The two
  grounding modes stay separate (§3.2 structured inventory vs §3.1 documents),
  and `test_no_kb_chunk_contains_a_broker_unit_id` enforces it. Real-estate
  cases are answered through the inventory connector, not through retrieval.
- [x] **Cross-tenant Qdrant leak proven to fail with the filter removed.**
  Sabotaged `_TenantScope._filter` to drop the tenant clause: 8 tests fail,
  including `test_search_never_returns_another_tenants_points` and
  `test_delete_cannot_reach_another_tenants_points`. Reverted; 23 pass.
- [x] **`edu-0015` retrieves its chunk.** `"fe manh fe kantara?"` →
  `sinai_discount_tuition_ar` at rank 1, on the synonym map plus the dense arm.
- [x] **`retrieval_recall_at_5` measured, not skipped, and above 0.85 on
  education.** 100.0% over the 10 gold-chunk cases, from the project's own
  runner on a live suite.
- [x] **`hallucinated_figure_rate` and `hedged_figure_rate` both zero.**
  **BOUNDED, 2026-08-20 — read this before citing the number.** The gate
  compares a reply's figures against the set of numbers in the retrieved
  passages, so a figure lifted from one passage and relabelled as something
  else passes it. edu-0012 stated the 500 EGP track-change fee as engineering
  tuition and the gate returned clean. This criterion was met as written and
  the wording was weaker than anyone reading it assumed: it means "no figure
  appeared that was absent from retrieval", not "no figure was hallucinated".
  Harness spec §2.1.1 has the analysis.
  0.0% and 0.0%, each over the 5 turns that stated a figure. Measured on the
  reply that was *sent*: §19.3 discards a composition holding an unsourced
  figure and sends a scripted reply, so the customer never receives it. The
  runtime gate rejected 4 of 11 compositions on that run — tracked separately,
  because it is the guard working rather than the metric failing.
- [x] **Webhook resolves tenants via `moc_lookup`; that role provably cannot
  read conversations.** 21 tests. The role's entire privilege surface is
  `[(channel_account_lookup, SELECT)]`, asserted through `aclexplode`, with no
  column grants and no `BYPASSRLS`.
- [x] **Handoff round trip works from the inbox.** 12 tests, plus
  `test_a_handed_off_conversation_shows_the_agent_what_happened`: webhook →
  worker → handoff → the inbox thread returns what the customer actually wrote.
- [x] **17 of 17 education cases run through both stages and produce a
  report.** The remaining 22 are real-estate; see P1b.

## P1b — blocked on the structured-inventory connector

Not deferred for time. Every line here needs the same missing piece: a
real-estate script and a connector that answers from `units.jsonl` under the
availability filter and the `as_of` disclosure, which is §3.2's grounding mode
and shares no code with the document retrieval P1 built.

Running the real-estate cases before it exists would report failures that
measure the absent connector rather than answer quality, and a metric whose
denominator is "cases we could not run" is worse than an unmeasured one.

- [ ] All 39 cases run through both stages — 17 today, the 22 real-estate
  cases blocked
- [ ] `arithmetic_in_model_rate` zero — fed by `check_tool_calls`, which only
  fires on cases pinning a calculator call, all of which are real-estate
- [ ] `type_substitution_rate` zero, measured against real inventory rather
  than skipped
- [ ] `invented_compound_rate` zero, measured against real inventory rather
  than skipped
- [ ] `sold_unit_offered_rate` and `asof_disclosure_rate` measured — both are
  gates in `config/evals/gates.yaml` that no run has ever fed

The deterministic checks behind all five already exist and are unit-tested in
`tests/evals/test_deterministic_checks.py`. What is missing is the path that
produces turns for them to grade.

## Carried out of P1 for a different reason

- [ ] **Agent authentication.** `AgentAuthenticator` is a Protocol with no
  default implementation, so the inbox is not deployable. A header-derived
  tenant id would be an authorization bypass wearing the shape of a feature,
  which is why it was left explicit rather than stubbed. P2.
- [ ] **Slot extraction.** The live suite runs a documented keyword stub in
  place of the extraction prompt, so `overall_accuracy` (5.9%) substantially
  measures the stub. The prompt is P2 work, and the accuracy figure should not
  be read as a quality baseline until it exists.

## Deliberately not in P1

- Instagram, Messenger, Email (P2)
- SIS lookup, CRM push, viewing calendar (P3)
- Billing, self-serve onboarding (P4)
- Tuning anything against eval numbers. **Read the first report; change nothing on the strength of 39 cases.** Both suites are still ~95% synthetic against targets of 150 and 80, and the gap closes with pilot traffic, not with tuning.

## Two constraints to keep in view

**3.3 GB RAM.** Qdrant, Meilisearch and Postgres already share this box, and Task 17 adds embedding batches. A self-hosted reranker will not fit — use an API. If ingestion OOMs, that is the resize conversation arriving, not a bug.

**Latency.** The measured model call is 2.7–5.0s. Retrieval, guards and the channel hop sit on top of that. Task 19 should record fusion latency from the first test rather than discovering it at the end.
