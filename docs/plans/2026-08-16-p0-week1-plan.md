# More Of Chat — P0 Week 1 Implementation Plan

> **For Claude:** implement this plan task-by-task. Run the test before writing the implementation. Commit after every task.

**Goal:** A running repo with enforced architectural boundaries, provably isolated multi-tenancy, and the deterministic half of the Arabic evaluation harness — the parts that need no LLM or channel credentials.

**Architecture:** FastAPI + Postgres 18 with row-level security, Valkey for queues, Qdrant + Meilisearch for retrieval (containers up but unused this week). The eval harness is a pytest suite that loads YAML cases and runs code-only checks. Stage 2 (LLM judge) lands in week 2.

**Tech Stack:** Python 3.14, uv, FastAPI, SQLAlchemy 2.x async, asyncpg, Alembic, pytest, pytest-asyncio, testcontainers, import-linter, ruff, Docker Compose.

**Prerequisite:** Docker 29 on Ubuntu 26.04. Note cgroup v1 is removed in 26.04 — if you carried a compose file from a 24.04 host, it may fail to start.

**Step 1: Write the failing test**

```python
# tests/test_infra.py
import socket, pytest


@pytest.mark.parametrize("port", [5432, 6379, 6333, 7700])
def test_service_reachable_on_localhost(port):
    with socket.create_connection(("127.0.0.1", port), timeout=2):
        pass


@pytest.mark.parametrize("port", [5432, 6333, 7700])
def test_service_not_exposed_externally(port, public_ip):
    """Regression guard: a compose edit must not republish these to 0.0.0.0."""
    with pytest.raises((ConnectionRefusedError, TimeoutError, OSError)):
        socket.create_connection((public_ip, port), timeout=2)
```

The second test is the one that matters on a VPS. It catches the day someone adds `ports: ["5432:5432"]` back while debugging and forgets to revert it. Supply `public_ip` as a fixture reading `MOC_PUBLIC_IP` from the environment, and skip the test when it's unset so the suite still runs locally.

**Step 2: Run to verify it fails**

Expected: FAIL — `ConnectionRefusedError`

**Step 3: Implementation**

```yaml
# compose.yaml
name: moc
services:
  postgres:
    image: postgres:18
    environment:
      POSTGRES_DB: moc_dev
      POSTGRES_PASSWORD: ${MOC_PG_PASSWORD}
    ports: ["127.0.0.1:5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s

  valkey:
    image: valkey/valkey:9
    ports: ["127.0.0.1:6379:6379"]
    command: valkey-server --save 60 1 --requirepass ${MOC_VALKEY_PASSWORD}

  qdrant:
    image: qdrant/qdrant:latest
    environment:
      QDRANT__SERVICE__API_KEY: ${MOC_QDRANT_KEY}
    ports: ["127.0.0.1:6333:6333"]
    volumes: ["qdrant:/qdrant/storage"]

  meilisearch:
    image: getmeili/meilisearch:latest
    environment:
      MEILI_MASTER_KEY: ${MOC_MEILI_KEY}
      MEILI_ENV: production
    ports: ["127.0.0.1:7700:7700"]
    volumes: ["meili:/meili_data"]

volumes: {pgdata: , qdrant: , meili: }
```

**Every port binds to `127.0.0.1`, not `0.0.0.0`.** On a public VPS this is not optional: Qdrant and Meilisearch have no authentication unless you set a key, and a bare `5432:5432` publishes Postgres to the internet. Docker writes its own iptables rules and will happily punch through `ufw`, so the bind address is your actual control, not the firewall.

Reach these services from your machine over an SSH tunnel:

```bash
ssh -L 5432:127.0.0.1:5432 -L 6333:127.0.0.1:6333 moc-dev
```

Pin the `latest` tags to explicit digests before this reaches staging. `latest` in a compose file is how a working environment silently changes underneath you.

```python
# migrations/versions/0002_rls.py  (upgrade body)
op.execute("""
CREATE TABLE conversations (
  id uuid PRIMARY KEY,
  tenant_id uuid NOT NULL REFERENCES tenants(id),
  state jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE conversations ENABLE ROW LEVEL SECURITY;
ALTER TABLE conversations FORCE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON conversations
  USING (tenant_id = current_setting('moc.tenant_id', true)::uuid)
  WITH CHECK (tenant_id = current_setting('moc.tenant_id', true)::uuid);

CREATE ROLE moc_app NOLOGIN;
GRANT SELECT, INSERT, UPDATE, DELETE ON conversations TO moc_app;
""")
```

`FORCE ROW LEVEL SECURITY` matters: without it, the table owner bypasses the policy, and your tests pass while production leaks. The app must connect as `moc_app`, never as the owner.

```python
# src/moc/tenancy/context.py
from contextlib import asynccontextmanager
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession


@asynccontextmanager
async def tenant_session(engine, tenant_id):
    async with AsyncSession(engine) as s:
        await s.execute(
            text("SELECT set_config('moc.tenant_id', :t, true)"),
            {"t": str(tenant_id)},
        )
        yield s
```

The `true` third argument scopes the setting to the transaction — critical with connection pooling, or a tenant id leaks into the next request on the same connection.
